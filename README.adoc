= unversioned-component-urls

Antora extension: bare `/component/` URL as version selector (default) or alias to latest.

link:https://github.com/antora-supplemental/antora-unversioned-component-urls/issues[Report Bug] ·
link:https://github.com/antora-supplemental/antora-unversioned-component-urls/issues[Request Feature]
endif::[]

== About The Project

Antora extension that gives **versioned** components a useful bare URL (`/component-name/`), with an explicit choice of policy:

* `selector` (default) — version chooser page
* `alias` / `alias_to_latest` — redirect to the latest version's start page

Upstream discussion:: https://gitlab.com/antora/antora/-/issues/291

Related Antora use case (alias mode):: https://docs.antora.org/antora/latest/extend/extension-use-cases/#redirect-from-component-to-latest-version

== Installation

=== From GitHub (current)

Pin a release tag when you can:

[source,shell]
----
pnpm add -D github:antora-supplemental/antora-unversioned-component-urls#v2.1.0
# npm
npm install -D github:antora-supplemental/antora-unversioned-component-urls#v2.1.0
# yarn
yarn add -D github:antora-supplemental/antora-unversioned-component-urls#v2.1.0
----

Floating `main` (gets fixes without a bump — less reproducible):

[source,shell]
----
pnpm add -D github:antora-supplemental/antora-unversioned-component-urls
----

=== Sibling checkout (local hack)

[source,shell]
----
pnpm add -D file:../antora-unversioned-component-urls
----

Package name:: `@antora-supplemental/unversioned-component-urls`  
Repo name:: `antora-unversioned-component-urls`

Former names (GitHub redirects the old repo URL):: `antora-alias-component-to-latest` / `@antora-supplemental/alias-component-to-latest` — update `require` / dependency keys to the new package name.

npm publish is optional later; GitHub install is enough for public use.

== Usage

=== Playbook

Register under `antora.extensions` (order relative to Lunr does not matter for this extension):

[source,yaml]
----
antora:
  extensions:
    - require: '@antora/lunr-extension'   # recommended on every site
    - require: '@antora-supplemental/unversioned-component-urls'
----

With only the package name (Node resolves `main` / `exports`):

[source,yaml]
----
antora:
  extensions:
    - '@antora-supplemental/unversioned-component-urls'
----

==== Modes

[source,yaml]
----
antora:
  extensions:
    - require: '@antora-supplemental/unversioned-component-urls'
      mode: selector              # default — version chooser page
      # mode: alias               # redirect /component/ -> latest start page
      # mode: alias_to_latest     # same as alias
      short_circuit_single: true  # default; one-version components alias through
----

| Mode | `/component-name/` becomes |
|====
| `selector` (default) | A page listing each numbered version (and marking latest), with xrefs into that version's start page |
| `alias` / `alias_to_latest` | A redirect to the latest version's start page (Antora docs snippet behavior) |
|====

Components that already have an empty / `version: ~` version are skipped in every mode.

=== Behavior

* Versioned URLs such as `/component-name/0.2.0/` keep working.
* Selector pages are real versionless ROOT `index.adoc` pages (not redirects), so relative links and UI chrome behave normally.
* With `short_circuit_single: true` (default), a component that has exactly one numbered version uses an alias instead of a one-item chooser.
* Antora camelCases playbook keys before they reach the extension (`short_circuit_single` → `shortCircuitSingle`). **2.1.1+** reads both shapes; older releases ignored the snake_case flag and always short-circuited.
* Page-level unversioned URLs (e.g. `/component-name/attributes.html` as a per-page chooser) are not implemented yet — component root only for now.

=== Requirements

* Antora 3.1+ (`@antora/site-generator` peer)
* Node 18+
